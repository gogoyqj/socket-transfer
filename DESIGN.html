Socket Transfer

WebSocket 消息中转服务 — 设计文档 v1.4
一、概述
📡

项目简介

手机和电脑没有公网 IP，无法直接建立 WebSocket 连接。通过中转服务器实现双向消息转发。

手机 (无公网 IP) ←—WebSocket—→ 中转服务器 (公网 IP) ←—WebSocket—→ 电脑 (无公网 IP) 只转发消息，不暴露端口，不做端口穿透
消息中转 非内网穿透 自用场景
二、安全分析
🔒

消息中转 vs 内网穿透

维度消息中转（本项目）内网穿透（frp/ngrok）
做什么转发应用层消息暴露内网 TCP/UDP 端口到公网
暴露面只暴露业务接口暴露整个端口（SSH、HTTP、数据库等）
协议只走 WebSocket 应用数据任意协议透传
攻击面小 — 攻击者只能发协议支持的消息大 — 可打暴露的任何服务
是否内网穿透❌ 不算✅ 就是
🛡️

安全措施

风险缓解措施
传输层窃听wss://（TLS 加密）— 必须
未授权访问uid + 64位 token 双因子认证（匿名注册，消费端需持有凭证）
暴力枚举64位 hex token（256位熵），不可能枚举
消息过大单条消息上限 1MB
滥用中转严格限制只有配对成功的客户端能通信

自用场景，wss:// + token 认证足够，不需要 E2EE。

三、权限控制模型
🔑

三个权限标志

标志作用性质格式
uid 用户身份 — 标识"你是谁" 客户端生成 11 位数字（随机生成）
token 认证凭证 — 证明"你有权" 客户端生成 64 位 hex 随机串
uuid 生产端连接 — 标识"连哪个" Producer 自动生成 UUID v4
cuuid 消费端标识 — 标识"谁在用" Consumer 自动生成 UUID v4
生产端 → 自动生成 uid + token + uuid → 匿名注册到中转服务器 消费端 → 用同样的 uid + token → 查询可用连接列表 [uuid...] 消费端 → 自动生成 cuuid → 选择 uuid → 建立消息转发通道

WebSocket 消息协议

WebSocket

客户端 → 服务器

type方向说明
register_transfer 生产端 → 服务器 注册连接，携带 uid, token, uuid, name
list_transfer 消费端 → 服务器 查询可用链接列表，携带 uid, token
subscribe_transfer 消费端 → 服务器 订阅指定链接，携带 uid, token, uuid, cuuid
transfer_produce 生产端 → 服务器 发送消息：{ data: { uuid, targetConsumer?, message } }
transfer_consume 消费端 → 服务器 回复消息：{ data: { uuid, message } }（服务端注入 cuuid）

服务器 → 客户端

type方向说明
transfer_list 服务器 → 消费端 链接列表：{ data: { list: [{ uuid, name }] } }
transfer_connect 服务器 → 消费端 订阅成功：{ data: { uuid } }
transfer_break 服务器 → 客户端 连接断开/错误：{ data: { code } }
transfer_error 服务器 → 客户端 业务错误（如消息过大）：{ data: { code, message } }
六、错误码
⚠️

错误码定义

code含义方向触发场景消费端行为
10001 生产端断开 → 消费端 生产端断开连接时立即推送 触发 onBreak，不自动重连
10002 订阅失败 → 消费端 鉴权失败或 uuid 不存在 提示鉴权或 uuid 错误
10003 鉴权失败 → 生产端 注册时 uid/token 不合法 —
10004 凭证变更 → 消费端 生产端重连时 token 变了 SDK 自动重新鉴权 + 重订阅
10005 消息过大 → 发送方 单条消息超过 1MB 提示消息过大
七、业务流程
🔄

消息流转全景

生产端(电脑) 中转服务器 消费端(手机) │ │ │ │── register_transfer ──────────────>│ │ │ { uid, token, uuid, name } │ (创建 Connection) │ │ │ │ │ │<──── list_transfer ──────────────│ │ │──── transfer_list ──────────────>│ │ │ { list: [{ uuid, name }] } │ │ │ │ │ │<──── subscribe_transfer ─────────│ │ │ { uid, token, uuid, cuuid } │ │ │ (创建 Forwarder, ID = cuuid) │ │ │──── transfer_connect ───────────>│ │ │ { uuid } │ │ │ │ │── transfer_produce ──────────────>│── Forwarder.send(message) ──────>│ │ { uuid, message } │ │ │ │ │ │<──── 注入 cuuid ─────────────────│<──── transfer_consume ───────────│ │ { uuid, cuuid, message } │ { uuid, message } │ │ │ │ │── transfer_produce ──────────────>│ (定向路由: targetConsumer=cuuid) │ │ { uuid, targetConsumer, msg } │── Forwarder.send(message) ──────>│ │ │ │ │ ╳ 断开连接 │ │ │ │ (5分钟倒计时) │ │ │──── transfer_break(10001) ──────>│ │ │ (销毁 Connection + Forwarder) │
🔌

① 匿名注册流程（生产端）

WebSocket
1
生产端自动生成凭证
客户端生成随机 uid（11位数字）+ token（64位hex），无需服务器预配置
2
发送注册消息
{ type: "register_transfer", uid, token, uuid, name }
3
服务器校验格式 + 自动入库
校验 uid（11位数字）和 token（64位hex）格式，首次注册自动存入 store
3
创建/替换 Connection
新 uuid → 创建；已存在 uuid → 接管旧连接的 subscribers
🔗

② 订阅链接流程（消费端）

WebSocket
1
消费端查询可用链接
{ type: "list_transfer", uid, token } → 返回 transfer_list
2
消费端订阅指定链接
{ type: "subscribe_transfer", uid, token, uuid, cuuid }
3
服务器创建 Forwarder
注册到 Connection.subscribers，返回 transfer_connect
📨

③ 转发逻辑

方向消息格式转发方式
生产端 → 消费端 { type: "transfer_produce", data: { uuid, targetConsumer?, message } } 有 targetConsumer → 定向发给该 Forwarder；无 → 广播给所有 subscribers
消费端 → 生产端 { type: "transfer_consume", data: { uuid, message } } 服务端注入 cuuid，通过 Connection.ws 转发 { uuid, cuuid, message }

转发时只传递 message 字段，不转发外层包装。消费端收到的是生产端的原始消息体。

八、边界情况处理
⚡

连接生命周期

场景处理方式
生产端断线重连（5分钟内）新 ws 替换旧 ws，subscribers 不动，继续转发
生产端重连时带不同 uuid视为新连接，旧连接走超时销毁流程
生产端重连时 token 变了更新 token → 推送 10004 给 subscribers → 清空 subscribers → SDK 自动重订阅
消费端断线立即销毁 Forwarder，从 subscribers 移除
消费端断线后重连需重新 subscribe_transfer，不会自动恢复
消费端收到 10004SDK 自动重新鉴权 + 重订阅（优先原 uuid，否则第一个可用）
消费端收到 10001触发 onBreak 回调，不自动重连
同一 uuid 重复注册新连接替换旧连接，接管旧 subscribers
同一消费端重复订阅去重：同一 ws 只允许一个 Forwarder
💥

并发与竞态

场景处理方式
生产端断开 + 消费端同时发消息消息静默丢弃（Connection 不存在）
生产端断开 + 消费端同时订阅返回 10002（链接不存在）
5分钟倒计时期间消费端发消息消息丢弃（生产端 ws 已断），消费端已收到 10001
服务器进程重启内存中所有连接丢失，客户端需重连（自用可接受）
📏

资源限制

限制项值说明
单条消息大小1 MB超过返回 10005
subscribers 数量不限自用场景无需限制
断线重连超时5 分钟超时后销毁 Connection
超时检查间隔30 秒定时清理过期连接
九、转发器设计
🔧

Forwarder 接口

参考 prime-agent/packages/ui-client/src/transport.ts 的 createCallbackTransport 模式：

interface Forwarder {
  id: string                    // cuuid: 消费者唯一标识，用于从 subscribers 中移除

  send(data: unknown): void     // 向消费端发送消息（生产端→消费端）
                                // 内部调用 consumerWs.send(data)

  destroy(): void               // 销毁转发器，移除所有监听
}

生命周期：

创建
消费端 subscribe_transfer 成功时创建
运行
双向转发消息
销毁
消费端断开 → 立即销毁
生产端断开 → 立即推送 transfer_break(10001)，5 分钟超时后销毁 Connection
十、客户端 SDK
💻

Producer SDK（电脑端）

import { createProducer } from "socket-transfer";

const producer = createProducer({
  url:     "wss://relay.example.com",
  uid:     "13800138000",
  token:   "a1b2c3...64chars",
  name:    "My Agent",           // 可选，默认 "producer"
});

console.log(producer.uuid);  // 自动生成的生产端连接标识

// 监听消费端发来的消息
// msg = { uuid, cuuid, message }
producer.onMessage((msg) => {
  console.log("Received from", msg.cuuid, ":", msg.message);
});

// 向所有订阅的消费端广播
producer.send({ text: "hello from producer" });

// 向特定消费端定向发送
producer.sendTo("cuuid-xxx", { text: "hello consumer" });

// 获取 per-consumer channel（自动路由）
const channel = producer.channel("cuuid-xxx");
channel.send({ text: "hello via channel" }); // 自动定向到该 consumer

// 典型用法：收到消息后用 channel 回复
producer.onMessage((msg) => {
  const ch = producer.channel(msg.cuuid);
  ch.send({ type: "response", data: "ok" }); // 只发给该 consumer
});

// 监听连接状态
producer.onStateChange((state) => {
  // "connecting" | "connected" | "disconnected" | "closed"
});

// 断线自动重连（默认开启）
// producer.close() 手动关闭
📱

Consumer SDK（手机端）

import { createConsumer } from "socket-transfer";

const consumer = createConsumer({
  url:   "wss://relay.example.com",
  uid:   "13800138000",
  token: "a1b2c3...64chars",
});

console.log(consumer.cuuid);  // 自动生成的消费端唯一标识

// 查询可用链接
const list = await consumer.listConnections();
// → [{ uuid: "my-agent-001", name: "My Agent" }]

// 订阅指定链接
consumer.subscribe("my-agent-001");

// 监听连接建立
consumer.onConnect((uuid) => {
  console.log("Connected to:", uuid);
});

// 监听生产端消息
consumer.onMessage((msg) => {
  console.log("Received:", msg);
});

// 向生产端发送消息
consumer.send({ text: "hello from consumer" });

// 监听断开事件
consumer.onBreak((code) => {
  if (code === 10001) console.log("生产端断开");
  if (code === 10004) {
    // SDK 自动重新鉴权 + 重订阅，onConnect 会再次触发
    console.log("凭证变更，自动重连中...");
  }
});

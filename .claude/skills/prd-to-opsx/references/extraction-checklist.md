# PRD多维提取清单

阶段二使用此清单逐项提取PRD内容。每个维度下的每一项都必须在PRD中主动寻找，找不到的**精确标记到子项级别**（如「步骤2的输入未说明」而不是「步骤序列未说明」）——这些将成为阶段三的歧义候选。

---

## 维度一：业务流程

### 主流程（Happy Path）
- [ ] 触发条件（用户执行什么操作触发此流程）
- [ ] 完整步骤序列（1→2→3…，每步有明确的主语和动作）
- [ ] 每步的输入和输出
- [ ] 流程结束的成功状态

### 异常分支
- [ ] 所有 if/else 分支（用户可能走哪条路）
- [ ] 每个错误场景（系统错误、用户错误、第三方错误）
- [ ] 错误时的用户提示或系统行为
- [ ] 超时、限流、并发冲突的处理
- [ ] 重复提交/幂等性要求（同一操作触发两次时的预期行为）

### 前置/后置条件
- [ ] 前置条件（执行此流程需要什么已存在/已完成）
- [ ] 后置条件（流程完成后系统状态的变化）
- [ ] 权限要求（谁有资格触发此流程）

### 优先级与分期

- [ ] 每个功能点的优先级标注（P0/P1/P2 或本期/下期/后续迭代）
- [ ] 是否存在 P1 及以后优先级的功能

### 异步副作用/通知

> → 涉及消息队列时对照 `structured-fields-checklist.md` **类型五**确认消息体结构

- [ ] 流程完成后是否触发异步任务（消息队列、定时任务等）
- [ ] 是否发送通知（站内信、邮件、短信、Push）
- [ ] 通知的触发条件（哪些步骤/状态变更触发）
- [ ] 通知内容模板（若PRD有规定）
- [ ] 异步任务失败时的重试策略与兜底行为

---

## 维度二：数据模型

### 实体定义

> → 字段列表不完整时对照 `structured-fields-checklist.md` **类型三**（DB表字段）；枚举字段取值不全时对照**类型六**（枚举/状态值）

- [ ] 所有涉及的实体/对象名称
- [ ] 每个实体的字段列表，每个字段包含：
  - 字段名
  - 数据类型（string/int64/bool/timestamp/enum...）
  - 是否必填
  - 约束（最大长度、取值范围、唯一性、外键...）
  - 默认值（如有）
- [ ] 字段枚举值（如状态字段，列出所有可能值）

### 实体关系
- [ ] 实体间关系（一对一/一对多/多对多）
- [ ] 外键约束
- [ ] 级联规则（删除/更新时的联动）

### 状态机（如有）
- [ ] 所有可能的状态值
- [ ] 允许的状态转换（哪些状态可以转到哪些状态）
- [ ] 触发每次状态转换的事件
- [ ] 文档明确禁止的转换（若PRD未说明，在阶段三提问）

---

## 维度三：接口契约

### 每个API端点

> → 字段不完整时对照 `structured-fields-checklist.md` **类型一**逐项检查，缺任一项即标注 `[需确认]`

- [ ] HTTP方法（GET/POST/PUT/DELETE/PATCH）
- [ ] 路径（含路径参数）
- [ ] 请求头要求（Authorization等）
- [ ] 请求体结构（每个字段：名称、类型、是否必填、说明）
- [ ] 成功响应结构（状态码 + 响应体字段）
- [ ] 所有错误响应（状态码 + 错误码 + 错误信息格式）
- [ ] 幂等性要求
- [ ] 分页方式（如有：cursor/offset，页大小范围）

### 第三方依赖

> ⚠️ 此节内容**几乎必然**在项目代码中找不到完整定义，提取时每一项都应标记为「需确认」，在阶段三统一向用户询问。
> → 确认内容对照 `structured-fields-checklist.md` **类型二**的完整子项清单

- [ ] 调用的外部服务列表（支付、短信、OSS、地图、推送…）
- [ ] 外部调用失败时的降级/兜底策略
- [ ] 每个外部服务的完整接口细节（对照 `structured-fields-checklist.md` **类型二**子清单逐项确认）

---

## 维度四：UI/交互

> ⚠️ 本维度**仅前端需求适用**。若PRD不包含UI/交互内容，跳过此维度。

### 控件状态
- [ ] 每个关键控件的状态集合（正常/禁用/加载中/错误/空）
- [ ] 状态转换时机（什么操作触发状态变化）
- [ ] 加载态的展示方式（skeleton/spinner/占位文字）

### 表单校验
- [ ] 每个表单字段的校验规则（必填/长度/格式/自定义）
- [ ] 校验触发时机（onChange/onBlur/onSubmit）
- [ ] 校验失败时的提示文案（若PRD有规定）
- [ ] 跨字段联动校验（如"确认密码"必须与"密码"一致）

### 交互反馈
- [ ] 操作成功的反馈（toast/跳转/刷新列表...）
- [ ] 操作失败的反馈（错误弹窗/内联提示...）
- [ ] 危险操作的二次确认
- [ ] 关键数据的实时展示/刷新策略

---

## 维度五：非功能需求

此维度直接影响技术方案选型和实现细节，**不得遗漏**。PRD 中常以一句话带过，提取时须主动寻找。

### 性能要求
- [ ] 接口响应时间要求（P99 / P95 / 平均）
- [ ] 吞吐量/QPS 要求（峰值和日常）
- [ ] 批量操作的数据量上限

### 数据规模
- [ ] 核心表预估数据量（影响索引设计）
- [ ] 单次查询/导出的数据量上限
- [ ] 数据增长趋势（影响分表/归档策略）

### 并发与一致性
- [ ] 是否有并发写入场景（影响锁策略/幂等设计）
- [ ] 数据一致性级别要求（强一致/最终一致）
- [ ] 是否需要分布式事务

### 可用性与容错
- [ ] SLA 要求（如 99.9% 可用性）
- [ ] 第三方依赖不可用时的降级策略
- [ ] 数据持久化要求（是否允许丢失）

### 安全与合规
- [ ] 数据脱敏要求（哪些字段不能明文存储/传输）
- [ ] 操作审计要求（是否需要记录操作日志）
- [ ] 访问控制粒度（角色级/资源级）
